# Memro v0.1.0 Release Notes

**Memro — Verified Memory Infrastructure for AI Agents**

Give your AI agents persistent memory across sessions: agent identity, memory storage, and hybrid retrieval through an API, SDKs, and MCP.

## Highlights

- **Sovereign Agent Identity**: Agents register local Ed25519 public keys with cryptographic proof-of-work; private keys never leave the machine. Requests can be signed with v2 Ed25519 signatures or use standard Bearer API tokens.
- **Hybrid Retrieval Engine**: Written in Go with PostgreSQL + pgvector. Combines semantic vector similarity with Reciprocal Rank Fusion (RRF) and full-text keyword indexing for high recall and precision.
- **Model Context Protocol (MCP)**: Native stdio and SSE MCP server (`memro-mcp`) giving Claude Code, Cursor, Codex, and any MCP client persistent cross-session memory without prompt engineering.
- **One-Command CLI**: `npx memro-cli connect` detects installed agent tools and configures them automatically with global or project-scoped MCP configs and instruction rules.
- **Multi-Language SDKs**: Official idiomatic SDKs for Python (`memro`), JavaScript/TypeScript (`@memro/sdk`), and Go (`github.com/memrohq/memro/sdk/go`).

## Quickstarts

### 1. Cloud & MCP (Fastest)
```bash
npx memro-cli connect
```
In your agent session:
- Say: *"Remember that our primary database is PostgreSQL 16 with pgvector."*
- Start a fresh session and ask: *"What database and extensions are we using?"*

### 2. Self-Hosted (Source Available)
```bash
git clone https://github.com/memrohq/memro.git
cd memro
cp .env.example .env
docker compose up -d
curl http://localhost:8081/health
```

## Known Limitations

- **Memory Evolution & Graphs**: Advanced multi-session causal graph evolution is under active development.
- **Embeddings**: Self-hosted default uses external embedding providers (e.g. OpenAI `text-embedding-3-small`) or embedding gateways; embedded local ONNX runtime is roadmap item for v0.2.
